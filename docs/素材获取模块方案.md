# 素材获取模块方案

> 范围：把 Banner 素材的解析和下载从预览工作台里拆出来。  
> 入口：`src/internal/material/service/acquire.go` 的 `Acquire`。  
> 工作台仍提供 `/api/preview` 和 `/api/review`。本模块不生成预览页，也不做 11 类判断。

## 1. 为什么拆开

`creative` 原来同时做两件事：给页面生成预览 HTML，以及为审核提取素材并下载图片。预览会改写 tracker、把 `mraid.js` 指到本地桩，并在缺尺寸时填 300×250。审核要保留原始 ADM、遍历每一个 bid，尺寸缺失时保持 0。两套规则放在同一个包里，预览上的改动会碰到审核结果。

网关送给 TMT 的也是素材内容：Banner 送 ADM，Video 和 Native 送 Bid Response。请求侧的 `imp.secure` 不在送审包里，TMT 结果里也没有这个字段。素材模块因此只接收工作台现在提交的 Bid Response 或裸 ADM。

## 2. 模块边界

```text
cmd/server
    |
    v
creative 工作台
    |                |
    |                +---- jev.Client（11 类送审）
    v
material.Acquire
    |---- parser：按 adm 识别格式
    |---- fetch：下载 Banner 创意图片
    +---- render：动态渲染入口，当前不调用
```

| 位置 | 职责 |
| --- | --- |
| `src/internal/material` | 解析 Bid Response，下载 Banner 图片，返回统一清单 |
| `src/internal/creative/preview` | 预览 HTML、tracker 改写、MRAID 桩，以及现有的 VAST、Native 展示 |
| `src/internal/creative/asset` | URL 协议分组、Unsecured Request、组装 JEV 请求 |
| `src/internal/creative/service` | `/api/preview` 仍走 `preview.Parse`；`/api/review` 先调用 `Acquire`，再做协议规则和送审 |
| `web/` | 页面不改。审核响应不再输出 `impSecure` |

`material` 不引用 `gin`、`creative` 和 `jev`。

`Acquire` 的签名是：

```go
func Acquire(ctx context.Context, input string, fetcher *fetch.Fetcher) (Result, error)
```

`Result.Bids` 是每个 bid 的清单，`Result.Files` 按 `sourceId` 保存已下载的图片字节。某一张图下载失败只把该来源标成 `obtained=false` 并写下 `fetchError`，不让整次获取失败。

## 3. 输入和格式

输入只有一段 Bid Response JSON，或一段裸 ADM。不读取 Bid Request，不关联 `imp.secure`。bid 上的 `impid` 仍保留，因为它就在 Response 里。

每个 bid 只看自己的 `adm`：

| 条件 | 去向 | 当前结果 |
| --- | --- | --- |
| 含 `<VAST` | `parser/video.go` | `UNSUPPORTED`，原因是「video 素材提取尚未实现」，素材列表为空 |
| Native JSON（顶层或 `native` 下有 `assets`） | `parser/native.go` | `UNSUPPORTED`，原因是「native 素材提取尚未实现」，素材列表为空 |
| 其余 | `parser/banner.go` | 静态解析，并下载创意图片 |

视频或原生占位不让整次请求失败。同一条 Response 里的 Banner bid 仍会出结果。`UNSUPPORTED` 不能被审核写成未违规，也不会因此调用 Hub。

预览里的 VAST 和 Native 展示留在 `preview_engine.go`，继续给人看。素材模块的占位只约束审核提取。

## 4. 统一清单

类型在 `src/internal/material/model/source.go`。`/api/review` 的 `bids` 直接使用这份结构。

| 字段 | 含义 |
| --- | --- |
| `bidPath` | 例如 `seatbid[0].bid[1]`；裸 ADM 为 `adm` |
| `crid`、`adomain`、`impid` | 来自该 bid，可空 |
| `w`、`h` | 响应或图片标签中的尺寸；没有则为 0，不填 300×250 |
| `admHash` | 原始 ADM 的 SHA-256 |
| `admTypes` | 实际出现的 `HTML`、`IMAGE`、`SCRIPT`、`IFRAME`、`MRAID`，可同时存在 |
| `parseStatus` | `OK`、`PARTIAL`、`FAILED`、`UNSUPPORTED` |
| `failure` | 失败或未实现原因；成功时为空 |
| `assets` | 来源列表 |

每条来源：

| 字段 | 含义 |
| --- | --- |
| `sourceId` | 同一次提取内稳定，`bidPath` 加序号 |
| `kind` | `image`、`text`、`script`、`iframe`、`url` |
| `value` | 地址或可见文案 |
| `fieldPath` | 例如 `seatbid[0].bid[0].adm`，通知字段则为 `.nurl`、`.burl`、`.lurl`、`.iurl` |
| `role` | `creative`、`tracker` 或 `dynamic` |
| `obtained` | 创意图片下载并确认是完整 JPEG 或 PNG 后为 true |
| `contentHash` | 图片字节的 SHA-256 |
| `fetchError` | 下载失败原因 |

状态含义：

- `OK`：ADM 可以解析，可见文案或主体图片已经列出，且没有未执行的脚本、iframe、MRAID。
- `PARTIAL`：结构可以识别，但缺少主体素材，或仍有未执行的动态依赖。已下载的 `iurl` 或静态图不把这个状态改成完整。
- `FAILED`：ADM 为空，或 HTML 无法形成可审核结构。
- `UNSUPPORTED`：识别为视频或原生，提取尚未实现。

这四个状态都不是合规结论。

## 5. Banner 当前实现

这一步覆盖静态图片 URL 和 HTML Banner。识别规则与原来的审核提取相同，并补上两处缺口。

已覆盖：

- `<img>` 的 `src`、`srcset`，以及元素内联样式里的 `url(http...)`。
- 可见文案只来自 HTML 文本节点。`script`、`style` 里的文字不进入文案。
- `<script src>` 记为 `script`，`<iframe src>` 记为 `iframe`，角色都是 `dynamic`。不执行脚本，不进入框架。
- `<a href>`，以及 bid 上的 `nurl`、`burl`、`lurl` 记为 `url`。`iurl` 记为创意图片。
- 出现 `mraid.js` 或 `mraid.` 时，`admTypes` 加上 `MRAID`。
- tracker 仍按地址中的 `impression.php`、`burl.php`、`click.php`、`simp.png`、`mmp_imp`，或 `left:-9999px`，或宽高都是 0 或 1 来判断。tracker 不下载。
- Jampp `core_main_image` 继续还原 `imgsrv` 后面的 CDN 原图。

这一步补上的缺口：

- ADM 整段是一条 `http` 或 `https` 地址、没有 HTML 标签时，记为一条创意图片。地址像 tracker 时角色仍是 `tracker`。
- `<style>` 正文里的 `url(http...)` 按图片提取。样式正文不进入可见文案。
- `<link rel="stylesheet">` 记为 `url`、`role=dynamic`，不下载。

下载约束留在 `material/fetch`：

- 只下载 `kind=image` 且 `role=creative` 的来源。
- 只接受 `http` 和 `https`。相对路径、空地址、带 `${` 的宏记为未取得。
- 重定向最多 3 次，每一跳重新检查主机。拒绝本机、链路本地、私网和云元数据地址。
- 响应体默认不超过 8MB。内容必须是完整 JPEG 或 PNG，以文件头为准。
- 宽高不再在下载时拒绝。320×50、300×250、728×90 可以取得并计算 hash。

送审尺寸仍由 `jev.ValidateImage` 把关：宽和高都要在 280 到 1568，总像素也在这个闭区间的面积内。超限图片保持 `obtained=true`，不发 Hub，对应标签为 `UNKNOWN`。

`${AUCTION_PRICE}` 只在预览生成页面、以及网关把 Banner 送给 TMT 时替换成 `AUDIT`。素材解析保留原始 ADM，不替换这个宏。带未替换宏的地址因包含 `${`，下载时记为未取得。

## 6. 尚未实现的 Banner 类型

类型可以同时存在。下面是后续实现顺序，不是互斥分类。有脚本、iframe 或 MRAID 时，当前状态保持 `PARTIAL`。

| 阶段 | ADM 类型 | 难度 | 处理 |
| --- | --- | --- | --- |
| 已完成 | 静态图片 URL | 低 | 解析地址并下载 |
| 已完成 | HTML Banner | 低 | 解析 DOM、图片、文本和 CSS |
| 未做 | HTML5 动态创意 | 中 | 浏览器执行后提取 DOM、资源和截图 |
| 未做 | Iframe | 中高 | 进入 frame 提取内部 DOM 和资源 |
| 未做 | JS Loader | 高 | 执行 JS，监听网络请求 |
| 未做 | 第三方 Ad Tag | 高 | 运行脚本并等待异步加载 |

`src/internal/material/render/worker.go` 的 `Render` 是后四类的入口。它现在返回「动态渲染尚未实现」。`Acquire` 不调用它，因此不会把空白结果写成 `OK`。

后续渲染放在独立 Chromium 里，由 `Render` 去调。不把浏览器放进处理预览请求的进程，也不复用预览页里的 MRAID 桩。那份桩会把 `mraid.getState` 固定成 ready，只适合给人看。动态阶段沿用现有安全边界：不点击、不访问落地页、不请求 tracker、限制跳转和体积、拒绝本机与内网地址。依赖 MRAID 才画出的画面保持 `PARTIAL`。

## 7. 审核怎么用这份结果

`Review` 调用 `Acquire` 之后：

1. `Classify` 和 `UnsecuredRequest` 只看来源清单里的地址。创意资源的 `http://` 才进入 Unsecured Request。`nurl`、`burl`、`lurl` 留在通知地址里。
2. 已取得且通过 `ValidateImage` 的创意图片，连同同 bid 的可见文案，按 `sourceId` 送给 Hub。
3. 没有可送审图片时不调用 Hub。相关标签为 `UNKNOWN`，`reviewError` 说明没有可送审的主体图片。

预览接口不走 `Acquire`。`/api/preview` 的返回、默认尺寸和 tracker 改写保持原样。
